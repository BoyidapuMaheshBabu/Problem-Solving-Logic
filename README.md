# Problem-Solving-Logic

A record of how I am developing Python problem-solving and reasoning skills through problems I have not solved before.

## Why I Started This Repository

When I entered my third year of diploma, Python became part of my semester subjects. I already enjoyed programming from learning **C in my first year** and **Java in my second year**, so I wanted to explore Python seriously.

I started Python from the basics, beginning with `print("Hello World")`, and reached conditional statements in about 15 days.

My usual learning approach is to learn a concept through college, self-study, or long-form learning resources, practice it, explore different ways of using it, and build small programs for fun while learning with classmates.

This repository grew from that learning process into something more focused: **using programming concepts to solve unfamiliar problems and improve my reasoning over time.**

## The Problem That Started It

While I was practicing Python, my brother was preparing for placement coding rounds and told me about the difficulty of passing test cases in a TCS coding round.

He shared a problem with me: a **Parking Fee Calculator** with multiple pricing rules and a discount condition. He encouraged me to treat it like a placement problem and try to solve it within the kind of time expected in a coding round.

I solved it in about **20 minutes**.

That experience made me realize that I enjoyed this kind of problem solving and wanted to challenge myself with more problems instead of only practicing isolated language exercises.

That became the beginning of this repository.

## How This Repository Evolved

After the first problem, I asked Claude for similar problems and started solving them one by one. Problems 01–08 were solved while I was working from my phone, and I began documenting the journey on GitHub so that my progress would remain visible over time.

Later, after getting my laptop and returning to the repository, I continued from Problem 09. The problems gradually became more data-oriented and required combining more Python concepts.

From the later problems onward, I also started asking for less familiar and more reasoning-focused problem scenarios, with the intention of eventually moving toward problems that are closer to the kind of thinking used before and around DSA.

The repository is therefore not only a collection of answers. It is a record of how my **reasoning, implementation, debugging, and code quality are developing.**

## How I Solve Problems Here

For the actual problem-solving work in this repository, I write the solution myself.

```text
Read the problem
      ↓
Try to solve it independently
      ↓
Identify what I don't know
      ↓
Learn the required concept
      ↓
Design my own approach
      ↓
Implement it myself
      ↓
Test and debug
      ↓
Review and improve
```

When a problem requires a concept I have not learned yet, I use AI to **learn and understand that concept**. After understanding it, I return to the problem and develop my own approach and implementation.

AI may help me as a teacher, but I do not use AI-generated final solution code as my answer to these problems.

## Progression

### Foundation — Problems 01–08

Started with Python fundamentals and focused on turning real-world rules into program logic using conditions, calculations, input handling, and validation.

Examples include parking fees, banking interest, movie tickets, e-commerce discounts, library fines, restaurant billing, employee salary, and overtime payment.

### Data-Oriented Problems — Problems 09–10

Moved from individual calculations toward working with collections of records using lists, dictionaries, loops, and reusable functions.

These problems focus on team and department payroll calculations and required combining multiple concepts.

### Data Processing — Problem 11

Applied Python to student and subject records, including grouping data, calculating averages, ranking results, identifying the hardest subject, and handling a failure threshold.

This stage required more structured data processing and combining several concepts in one problem.

## Improving Earlier Solutions

As my understanding improves, I may revisit an earlier problem and add a **refactored solution** when there is a meaningful improvement in readability, structure, validation, reuse, or maintainability.

The original solution is kept because it represents an earlier stage of my thinking.

```text
Original Solution
      ↓
Review
      ↓
Identify Improvements
      ↓
Refactor
      ↓
Compare
      ↓
Learn
```

The purpose is not to hide earlier work. It is to show how my solutions change as I learn more.
